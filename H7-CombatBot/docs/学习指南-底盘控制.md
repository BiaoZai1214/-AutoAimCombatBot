## 1. 先理解硬件：四个电机怎么让车走

### 1.1 麦轮（Mecanum Wheel）原理

普通车轮只能前进后退+转弯。麦轮在轮毂上斜装了自由滚子，四个轮子配合就能**横着走、斜着走、原地转**。

汽车不能横移 → 差速底盘不能横移 → **麦轮可以**，因为滚子把"旋转"转化成了"侧向滑移"。

O型安装（四个轮子的滚子从上面看呈O形）：  
看图就懂 → 网上搜 "mecanum wheel O-configuration"

### 1.3 电机驱动：TB6612

**位置**：`BSP/tb6612/tb6612.c`

TB6612 是一片双H桥电机驱动。每路电机需要 3 根线：
- **IN1/IN2**：方向控制（01=正转, 10=反转, 00/11=刹车）
- **PWM**：速度控制（占空比决定转速）

```c
// 核心函数：4个电机同时设置
void TB6612_SetMotorSpeed(int16_t m1, int16_t m2, int16_t m3, int16_t m4);
// 正数=正转, 负数=反转, 范围 ±4199
```

TIM1 产生 4 路 PWM（CH1-4, 20kHz），ARR=4199。  
**学习时改**：尝试把 `TB6612_SetMotorSpeed(1200,1200,-1200,-1200)` 改为别的值，看自检时四个轮子怎么转。

### 1.4 编码器：TIM2-5 四路正交编码器

**位置**：`BSP/encoder/encoder.c`

每个电机后面有一个霍尔编码器（13线 × 30减速比 × 4倍频 = 1560脉冲/圈）。  
每 20ms 读一次计数器并清零，得到"这段时间轮子转了多少"。

```c
// 读取 → 清零，典型的差分测速模式
enc = Encoder_GetCounter(ENCODER_A);
Encoder_ClearCounter(ENCODER_A);
R_Wheel[0].RT = enc * WHEEL_SCALE * PID_RATE_HZ;  // → 实际速度 m/s
```

**关键公式**：`WHEEL_SCALE = PI × 轮径 / 编码器分辨率 = 3.1416 × 0.080 / 1560`  
乘以 `PID_RATE_HZ(50)` 是因为编码器是每帧的增量，要换算成每秒。

## 2. 核心算法：robot.c 完整拆解

### 2.1 调用流程

`Robot_Kinematics()` 每 20ms 调用一次，五个步骤串行执行：

```
ReadEncoders()       → 读编码器 → 各轮实际速度 RT (m/s)
ForwardKinematics()  → 正运动学 → 底盘实际速度 (Vx, Vy, Vw)
ClampTarget()        → 目标限幅 → 防止超速
InverseKinematics()  → 逆运动学 → 各轮目标速度 TG (m/s)
PID_Update()         → PD速度环 → 输出PWM给TB6612
```

### 2.2 正运动学：轮速 → 底盘速度

```
Vx = (A + B + C + D) / 4      → 四个轮一起转 = 前进
Vy = (-A + B + C - D) / 4      → 对角轮配合 = 横移
Vw = (-A + B - C + D) / (4*R) → 一侧正一侧反 = 旋转
```

其中 R = (轮距+轴距)/2 = 0.153m。这就是"从四个轮子反算车在怎么动"。

### 2.3 逆运动学：底盘目标 → 各轮目标

```
A.TG = Vx - Vy - Vw*R     左前
B.TG = Vx + Vy + Vw*R     右前
C.TG = Vx + Vy - Vw*R     左后
D.TG = Vx - Vy + Vw*R     右后
```

这是麦轮的核心公式。**矩阵形式**就是：

```
[轮A]   [ 1  -1  -R ] [Vx]
[轮B] = [ 1   1   R ] [Vy]
[轮C]   [ 1   1  -R ] [Vw]
[轮D]   [ 1  -1   R ]
```

**动手验证**：假设 Vx=1, Vy=0, Vw=0 (纯前进)，四个轮都是 +1，合理。  
假设 Vx=0, Vy=1, Vw=0 (纯右移)，A=-1, B=+1, C=+1, D=-1，对角配合。  
假设 Vw=1 (纯旋转)，A=-R, B=+R, C=-R, D=+R，左侧全反右侧全正，原地转。

### 2.4 PID 速度环（关键）

**用的是纯增量式PD，没有 I（积分）项**。

```c
bias = target - actual;        // 误差 = 期望 - 实际
pwm += kp*bias + kd*(bias - bias_last);  // 增量累加
pwm = clamp(pwm, ±4199);
bias_last = bias;
```

| 参数 | 值 | 含义 |
|------|-----|------|
| KP | 800 | 比例项：误差越大，PWM加得越多 |
| KD | 1000 | 微分项：误差变化越快，阻尼越大（防过冲） |
| 限幅 | ±4199 | 对应 TIM1 ARR 值 |

**为什么用增量式？** 不用保存历史误差和，代码简单；误差变化时的阻尼效果好。

**为什么没有 I 项？** I 项消除稳态误差，但也会导致积分饱和（急停时轮子继续转）。这个底盘用 PD 就够了，因为：
- 麦轮底盘本身阻尼大，稳态误差小
- 刹车逻辑（下面讲）替代了 I 项的归零功能

### 2.5 刹车逻辑

```c
if (TG == 0) {
    // 四级衰减：>400 → -300, >100 → -80, 否则 → 0
    // 不经过 PID，直接暴力减速
}
```

当摇杆回中（TG=0），不经过 PID 计算，直接用多级衰减让 PWM 快速归零。  
2-3 帧（40-60ms）就能停下来。这比 PID 自己收敛快得多。

## 3. 学习路径（动手顺序）

### 第一步：看懂数据流向（30分钟）

打开 `App/ui.c` 的 `Control_Task`，画出数据流图：
```
PS2摇杆 → PS2_DriveControl → Robot_SetTarget → Robot_Kinematics → TB6612 → 电机
                                                       ↑
                                                  编码器反馈
```

### 第二步：改一个参数看效果（20分钟）

1. 把 KP 从 800 改到 400 → 编译烧录 → 推摇杆，感觉加速变慢了没
2. 改回 800，把 KD 从 1000 改到 500 → 急停时会不会来回晃（过冲）
3. 恢复参数

### 第三步：理解运动学公式（30分钟）

在纸上画一个麦轮 O 型布局，标上 A(左前) B(右前) C(左后) D(右后)，然后手动算：
- 推摇杆纯前进 → 四个轮的速度和方向
- 推摇杆纯右移 → 四个轮的速度和方向
- 推摇杆纯旋转 → 四个轮的速度和方向

### 第四步：理解PID（30分钟）

在 `PID_Update` 里加 printf 把 bias 和 pwm_out 打出来（需要接串口），观察：
- 推摇杆一瞬间：bias 很大 → pwm 加很多 → 电机加速
- 速度追上后：bias 变小 → pwm 缓慢增加（稳态保持）
- 摇杆回中：TG=0 触发刹车 → pwm 直接衰减

### 第五步：修改摇杆映射（选做）

打开 `App/ps2_control.c`：
- `g_speed = 12` 改速度倍率
- `* 13 / 10` 改横向补偿系数
- `step_map[4]` 改按键动作

## 5. 常见问题和排查

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 前进/后退往一边偏 | 某个电机正负极接反 | 单独驱动每个电机，确认方向 |
| 推摇杆没反应 | PS2 扫描失败 | 检查 SPI2 连接、PS2 指示灯 |
| 车轮一顿一顿 | 编码器计数异常 | 检查 TIM2-5 正交编码器模式 |
| 推摇杆速度不对 | speed 参数或 KP 问题 | 改 speed 看变化 |
| 急停后轮子还慢慢转 | 刹车衰减设太大 | 调小衰减步幅 |
| D-Cache 问题 | MPU 配置丢失 | CubeMX后检查Region3 |
