# 自瞄步战车 — 自瞄（视觉追踪）学习指南

## 学习目标

理解二自由度舵机云台的硬件控制、ESP-S3视觉识别+I2C通信协议、手动/自动追踪模式切换。  
学习后应能：独立配置舵机角度范围、理解I2C通信协议、添加新的ESP-S3交互命令。

---

## 1. 整体架构

```
ESP-S3-CAM         I2C1(100kHz)         STM32H750            TIM15(50Hz PWM)      舵机
┌──────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────┐
│ 视觉识别  │ -> │ pan_hi/lo    │ -> │ 读取角度指令  │ -> │ CCR1/CCR2   │ -> │ PAN(左右)│
│ PID计算   │    │ tilt_hi/lo   │    │ 限幅+去重    │    │ 500~2500us  │    │ TILT(俯仰)│
│ 目标跟踪  │    │ 4字节返回     │    │ 写舵机寄存器  │    │ 对应 ±90°   │    │ DS3218   │
└──────────┘    └──────────────┘    └──────────────┘    └──────────────┘    └──────────┘
```

**核心设计理念**：计算全部放在ESP-S3上做。STM32只负责"收角度 → 写舵机"，不做任何视觉计算。

## 2. 舵机控制

### 2.1 硬件

| 项目 | 参数 |
|------|------|
| 舵机型号 | DS3218 数码舵机 |
| 数量 | 2个（PAN左右、TILT俯仰） |
| 控制信号 | PWM 50Hz，脉宽 500~2500us |
| 角度范围 | ±90°（脉宽 1500us 为中位） |
| 定时器 | TIM15（PA2=CH1=PAN, PA3=CH2=TILT） |
| 关键寄存器 | PSC=199, ARR=19999 → 50Hz |

### 2.2 关键文件

| 文件 | 内容 |
|------|------|
| `BSP/servo/servo.c` | 舵机驱动：TIM15初始化、角度→脉宽转换、死区控制 |
| `BSP/esp_s3/esp_s3_i2c.c` | I2C1驱动：PB8/PB9, 100kHz, 读写ESP-S3 |
| `App/tracking.c` | 视觉追踪：底层I2C读取→限幅→写舵机 |
| `App/ps2_control.c` | PS2摇杆手动控制舵机 + SELECT切换追踪模式（第58行起） |

### 2.3 舵机驱动核心

**位置**：`BSP/servo/servo.c`

```c
// 角度 → 脉宽换算
us = 1500 + angle * 10 / 9;
// angle=0   → 1500us (中位)
// angle=900 → 2500us (右/下极限, +90°)
// angle=-900→ 500us  (左/上极限, -90°)
```

**软件死区 3us**：角度变化小于 3us（约0.27°）不更新CCR。  
这是为了避免数码舵机高频调节时的滋滋声和微抖动。

```c
if (diff < DEADBAND) return;  // 不写CCR，减少EMI和舵机抖动
```

**注意**：`Servo_Tick()` 当前为空函数。TIM7 的 20ms 中断已预留，但舵机本身是硬件 PWM 输出，不需要软件干预。舵机自闭环，PWM 脉宽定了它自己就会转到那个位置。

## 3. ESP-S3 通信

### 3.1 I2C1 硬件

| 项目 | 参数 |
|------|------|
| 引脚 | PB8(SCL) / PB9(SDA) |
| 功能复用 | AF4 (I2C1) |
| 速度 | 100kHz (标准模式) |
| 模式 | 开漏 + 上拉 |
| ESP地址 | 7-bit, 0x52 |

### 3.2 I2C 通信协议

**H7（Master）→ ESP-S3（Slave, 0x52）**

```
步骤1: H7 写 1 字节 → ESP (指定命令)
步骤2: H7 读 4 字节 ← ESP (返回数据)
超时: 20ms
```

| H7 写入命令 | ESP 返回 4 字节 | 说明 |
|------------|----------------|------|
| `0x10` | pan_hi, pan_lo, tilt_hi, tilt_lo | 舵机目标角度 (int16 ×2, 单位 0.01°) |

**角度格式**：
- 每个角度占 2 字节，大端序 (MSB first)
- pan = (buf[0] << 8) | buf[1]，单位 0.01°
- 范围 ±6000（即 ±60.00°）
- tilt 同理，占 buf[2]和 buf[3]

**为什么用 0.01° 精度？** ESP32 用浮点做 PID 计算，结果乘 100 变成整数传给 H7，避免浮点传输的精度丢失。

### 3.3 数据接收代码

**位置**：`BSP/esp_s3/esp_s3_i2c.c` → `ESP_S3_ReadServoCmd()`

```c
HAL_I2C_Master_Transmit(&hi2c1, addr, &reg_0x10, 1, 20);  // 发命令
HAL_I2C_Master_Receive(&hi2c1, addr, buf, 4, 20);          // 收4字节
cmd->pan  = (buf[0]<<8) | buf[1];   // MSB first
cmd->tilt = (buf[2]<<8) | buf[3];
```

如果 ESP32 不在线，HAL_I2C 会 timeout 20ms 后返回 HAL_ERROR，不阻塞主循环。

## 4. 追踪逻辑

### 4.1 状态机

**位置**：`App/tracking.c`

```
         SELECT按键
  手动 ←──────────→ 自动追踪
(摇杆控舵机)      (ESP-S3控舵机)
```

**核心变量** `Tracking_t`：
| 字段 | 含义 |
|------|------|
| enabled | 1=追踪模式, 0=手动模式 |
| locked | 1=已锁定目标, 0=未锁定 |
| confidence | 置信度 0-100 |
| pan/tilt | 当前舵机角度(0.1°) |

### 4.2 目标丢失处理

```
读取失败 → hold_cnt++
hold_cnt < 10 → 保持上次角度 (短暂遮挡不丢)
hold_cnt ≥ 10 → locked=0 (丢失200ms后解锁)
读取成功 → hold_cnt=0, locked=1, confidence=80
```

**为什么是 10 帧？** 20ms × 10 = 200ms，足够过滤瞬时遮挡，又不会让云台在真正丢失后傻等太久。

### 4.3 角度去重

```c
if (out_pan != last_pan) {
    Servo_SetAngle(SERVO_PAN, out_pan, 0);
    last_pan = out_pan;
}
```

舵机层已经做了 3us 死区，追踪层再做一次角度去重：目标角度没变就不调 `Servo_SetAngle`。双层保护，确保舵机只在真正需要时才动。

### 4.4 手动舵机控制

**位置**：`App/ps2_control.c:58-103`

当 `g_tracking.enabled == 0`（手动模式）时，L1/L2/R1/R2 控制舵机：

| 按键 | 动作 | 角度变化 | 步幅 |
|------|------|---------|------|
| L2 | PAN 右 | +12° | 12°/帧 |
| R2 | PAN 左 | -12° | 12°/帧 |
| L1 | TILT 上 | +12° | 12°/帧 |
| R1 | TILT 下 | -12° | 12°/帧 |

**消抖机制**：3帧消抖（DB_THRESH=3），每帧 20ms，稳定按下 60ms 才触发一次动作。避免按键抖动导致舵机跳动。

**范围限幅**：pan/tilt 累积在 ±900（即 ±90°）内，防止舵机打到机械限位。

### 4.5 模式切换

**SELECT 按键下降沿触发**：
```c
if (prev_sel && !cur_sel && cooldown == 0) {
    Tracking_Toggle();       // 翻转 enabled
    cooldown = 15;           // 300ms 冷却防连发
}
```

**为什么要释放才切？** 防止按着 SELECT 不放时反复翻转模式。300ms 冷却是为了防止按键抖动导致的误触发。

## 7. 常见问题

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 舵机不动 | TIM15 没启动 / 引脚不对 | 用示波器看 PA2/PA3 有无 50Hz PWM |
| 舵机一直滋滋响 | 死区太小 / 舵机本身问题 | 换一个舵机试试 |
| ESP 读不到数据 | I2C 通信失败 | 确认 PB8/PB9 连接，测量上拉电阻 |
| 追踪模式舵机抖动 | ESP-S3 PID 过调 | 调低 ESP 端 PID P 项 |
| SELECT 按键不灵敏 | 按键消抖太久 | 减小 DB_THRESH |
| SELECT 来回跳 | 冷却时间太短 | 增大 cooldown 值 |

## 8. 深入理解：为什么 ESP-S3 做计算而 STM32 只转发

这是一个典型的**算力分离**设计：

```
ESP-S3 (双核 240MHz + NPU)
├─ 摄像头采集 (DCMI/DVP)
├─ 颜色识别 / 神经网络推理
├─ 目标位置 PID 计算 → 舵机角度
└─ I2C Slave 等待 STM32 来读

STM32H750 (400MHz Cortex-M7)
├─ 底盘 4 路 PID (每 20ms)
├─ PS2 手柄扫描
├─ LCD 刷新
├─ W5500 以太网
└─ 定时过来读一下 I2C → 写舵机
```

如果 STM32 自己跑视觉，会严重影响底盘控制（底盘控制是硬实时任务）。分离后各司其职：
- **ESP-S3**：慢一些没关系，追踪抖动不影响安全
- **H7**：控制循环必须在 20ms 内完成，不能被打断

**I2C 为什么不阻塞？** `timeout=20ms`，ESP 没连上不会死等。`ESP_S3_Init()` 在 Control_Task 开头调用，失败也不影响后续任务启动。
